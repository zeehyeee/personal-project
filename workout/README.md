# 운동 기록 웹앱

삼성헬스 캡처를 읽어 Google Sheets에 쌓고, 원하는 양식(캘린더·추이·주간 리포트)으로 보여주는 개인 앱.
이 폴더는 저장소 루트의 Next.js 앱과 독립적이다. (빌드 단계 없음, 의존성 없음)

## 구조

```
workout/
  vercel.json       정적 사이트로 배포 (https://workout-log-olive.vercel.app)
  index.html        단일 HTML 프런트, src/*.js 를 ES 모듈로 불러온다
  styles.css        뼈대 스타일 (위계·구조만, 비주얼 마감은 Claude Design 단계)
  dev.js            로컬 확인용 정적 서버
  api/extract.js    (예정) Vercel 함수: Claude 비전으로 캡처 추출. API 키는 환경변수에만
  src/              브라우저·Node 공용 모듈
    app.js          앱 뼈대: 헤더, 하단 탭, 화면 전환(#calendar, #weekly, #trend, #detail/날짜/종목)
    ui.js           화면 공용 헬퍼 (이스케이프, 아이콘, 수치 표기)
    views/          화면별 렌더링 (calendar, weekly, detail, add, capture)
    store.js        저장소 (지금은 localStorage, 나중에 Sheets로 교체)
    demo.js         예시 데이터: 보내준 실제 기록 (source: 'demo', 화면에서 한 번에 지울 수 있음)
    manual.js       직접 입력 폼 → 세션
    capture/        캡처 추출 (아래 설명)
    aggregate.js    세션 → 일 합산
    swim.js         수영 구간 기반 페이스·SWOLF, 휴식 구간 제외, 빠진 구간 검사
    streak.js       스트릭, 이번 달 운동일
    compare.js      평소 대비(직전 4주 / 3개월), 증감률
    habit.js        습관 지수
    duplicate.js    중복 판정
    dates.js        날짜·주차·연도 추정
  test/             node --test 단위 테스트
```

실행: `cd workout && npm run dev` → http://localhost:5173
테스트: `npm test` (Node 22, 설치할 것 없음)

## 확정한 결정 (명세 보완)

- **주 시작 요일**: 일요일. 월 캘린더와 주간 리포트(미니 캘린더 띠, 평소 대비, 습관 지수) 모두 일~토 기준.
  1일이 포함된 행이 그 달 1주차.
- **하루 수영 여러 번**: 휴식 구간은 세션별 중앙값으로 판정하고, 페이스·SWOLF·영법별 값은
  그날 모든 세션의 구간을 모아 다시 계산한다. (세션 값끼리 평균 내지 않음)
- **중복 판정**: 같은 날짜·종목에서 둘 다 시작 시각이 있으면 시작 시각 일치,
  한쪽이라도 없으면(직접 입력) 운동 시간 차이 1분 이내. 저장을 막지 않고 건너뛸지 고르게 한다.
- **이번 달 운동일**: 분모는 오늘 날짜다. `이번 달 5/8일` (8일 중 5일 운동). 매일 운동이 목표라서.
  월 활동일 목표(settings `monthly_active_days_goal`, 20)는 목표 달성 점수에 쓴다.
- **연도 추정**: 오늘 기준 가장 최근의 과거 날짜로 보고 요일로 검증한다. 요일이 다르면 확인 화면에서 수정 요청.
- **페이스·속도 합산**: 거리가 있는 세션만으로 총 시간 ÷ 총 거리. 심박·케이던스는 값이 있는 세션만 시간 가중 평균.

## 화면 구성 (명세에서 바뀐 점)

- **하단 탭 3개: 캘린더 · 주간 · 추이.** 캘린더의 세로 주차 라벨과 헤더의 리포트 아이콘은 없앴다.
  주간 탭은 캘린더에서 고른 날짜가 있는 주로 열리고 `‹ ›`로 주를 넘긴다.
- **스트릭은 캘린더 위 한 줄.** `🔥 운동 N일차 · 이번 달 N/오늘날짜일`. 오늘 기록이 없으면
  `어제까지 N일 · 오늘도 이어가요`, 끊겼으면 `오늘 운동하면 1일차`.
- **선택한 날 타일**: 운동 시간(크게) + 거리(작게)를 한 줄에. 수영은 m, 나머지는 km.
- **추이 탭 일별 그래프(4단계 예정)**: 삼성헬스 전체보기처럼 가로로 넘기며 날짜별 막대를 보고,
  가운데 날짜의 합계를 아래에 보여준다. 평균선과 직전 기간 대비로 늘었는지 확인한다.

## 추이 탭

`src/trend.js`(계산) + `src/views/trend.js`(화면)
- 종목 캐러셀: 전체 → 걷기 → 달리기 → 자전거 → 수영. 화살표·점·스와이프. 카드에 이번 달 누적
- 기간 알약: 일별(최근 8주) / 주별(최근 12주) / 월별(최근 12개월). 막대를 가로로 넘겨 보고, 처음엔 오늘이 보인다
- 막대 값: 걷기·자전거=분, 달리기=km, 수영=m, 전체=운동 시간(분). 기록 없는 기간은 얇은 회색 막대
- 점선 평균선: 기록이 있는 기간의 평균
- 막대를 누르면 그 기간 합계, 주별·월별은 직전 기간 대비 %. 일별은 `자세히 보기`로 상세 화면
- 이번 달 요약: 월 누적, 운동한 날, 지난달 대비

## 주간 리포트

`src/report.js`(계산) + `src/views/weekly.js`(화면). 주는 일~토.
- 기간 배지·헤드라인(운동 시간 비중이 가장 큰 종목), 미니 캘린더 띠(4종목=진하게, 일부=연하게)
- 통계 4개(운동 시간, 활동일, 총 이동거리, 총 칼로리) + `평소보다 …` (평소 = 직전 4주 평균)
- 종목별 운동량(운동 시간 기준 막대, 거리·칼로리는 작게)
- **이번 주 나의 변화** (규칙 기반, API 없음, 최대 4개):
  새 영법 시작, 영법별 구간당 스트로크 감소(직전 4주 대비 0.3 이상), 수영 페이스 3초 이상 빨라짐,
  처음으로 N구간 쉬지 않고 수영, 한 번에 쉬지 않고 달린 최고 시간, 처음·오랜만에 한 종목,
  누적 이정표(달리기 10/25/50/100km…, 수영 1/5/10km…), 수영 N개월차, N일 연속, 평소 대비 활동일
- 습관 지수: 최근 6주 꺾은선 + 이번 주 점수 + 4주 전 대비
- 캘린더 탭 아래: 지난주에 운동했으면 `N월 N주차 리포트가 도착했어요` 카드

## 캡처 추출 (0원, 휴대폰 안에서)

`+ 기록 추가 → 캡처로 추가`에서 삼성헬스 캡처를 여러 장 고르면 된다. 서버·API 키·비용 없음.
Tesseract.js(무료 OCR)를 CDN에서 처음 한 번 받고(한글+영문 약 3MB), 캡처는 휴대폰 밖으로 보내지 않는다.

`src/capture/`
- `extract.js` 캡처 1장 → 화면 종류와 값. 원래 크기로 한 번 읽어 화면 종류·줄 위치를 찾고,
  필요한 줄만 2배로 키워 다시 읽는다(회색 날짜·시각이 정확해진다)
- `digits.js` 수영 구간 화면 숫자는 OCR 대신 **숫자 모양 템플릿**으로 읽는다(한 자리 숫자를 OCR이 자주 놓쳐서).
  실제 캡처의 숫자 232개로 만들었고 108/108 정확
- `parse.js` 글자 → 값. `10월`이 `102`로, `7:28`이 `728`로 깨지는 경우도 받는다
- `merge.js` 여러 장 → 세션. 같은 종목에서 운동 시간이 같은 값끼리 묶고, 겹치거나 중복된 구간 화면은 구간 번호로 합친다
- `engine-browser.js` 브라우저 OCR 연결

| 화면 | 가져오는 것 |
|---|---|
| 전체보기(일별) | 날짜, 세션별 시작 시각·운동 시간·거리(수영은 칼로리), `N세션` (빠진 세션 안내) |
| 결과 헤더 | 날짜, 시작 시각 |
| 운동 상세정보 | 운동 시간, 거리, 칼로리, 평균 심박, 평균 케이던스(달리기), 수영 반복횟수·총 스트로크 |
| 수영 구간 | 구간별 영법·시간·스트로크 (시간 기준·스트로크 기준 화면, 스크롤 여러 장) |
| 그 밖(지도, 그래프, 강도, km 구간) | 건너뜀 |

검증: 실제 캡처 18장(지도·그래프·중복 포함) → 세션 5개, 수영 18구간을 모두 맞게 읽음
(`test/fixtures/capture-items.json`, `test/capture-merge.test.js`). 헤드리스 브라우저에서 18장 47초.

## 저장하는 데이터 (sessions 시트)

`id, date, start_time, sport, duration_sec, distance_m, kcal, avg_hr, avg_cadence(달리기만), swim_laps, swim_total_strokes, source`
- 평균 페이스·속도는 저장하지 않고 시간 ÷ 거리로 계산한다
- 삼성헬스의 수영 평균 페이스·SWOLF(휴식이 섞인 값), 최고값, 고도, 총 시간, 걷기 케이던스는 저장하지 않는다
- swim_laps 시트: `session_id, lap_no, stroke, time_sec, strokes`

## 디자인 토큰

`styles.css` 상단 `:root`에 모았다. 토스 디자인 시스템(TDS)을 참고했고, 공식 문서
(developers-apps-in-toss.toss.im)를 이 환경에서 열 수 없어 널리 알려진 값 기준이다. 확인 후 조정.

목표치 기본값은 `src/sports.js`의 `DEFAULT_SETTINGS` (임시값).
